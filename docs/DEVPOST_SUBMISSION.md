# Devpost submission copy

## Project name

WatchTower

## One-line description

Human-governed multi-agent incident intelligence that detects streaming failures in ClickHouse,
quantifies business impact, and drafts a reversible response for approval.

## Inspiration

Streaming platforms produce high-volume delivery signals, but operators still lose time translating
dashboard anomalies into a cause, business impact, and safe action. WatchTower closes that gap while
preserving the human decision boundary required for high-stakes operational work.

## What it does

WatchTower continuously ingests a fully fictional streaming catalog and synthetic telemetry across
five regions. It compares live behavior with rolling baselines, detects view drops, buffering spikes,
and ad-delivery failures, correlates the signal with CDN evidence, calculates viewer-hours and USD
impact, and asks four specialized agents to produce a concise incident brief. The brief remains
pending until a human approves or dismisses it. No operational change executes automatically.

## How we built it

- Google Agent Development Kit 2.8 with a four-agent `SequentialAgent` workflow.
- Gemini on Vertex AI as the only runtime AI provider.
- ClickHouse for live telemetry and versioned incident state.
- Official `mcp-clickhouse` over container-local stdio for all analytics reads.
- FastAPI and a responsive, dependency-free web dashboard on Cloud Run.
- Separate ingestion/read-only identities, query middleware, Secret Manager, and cost-bounded Cloud
  Run settings.

## Data sources

No third-party media catalog or private streaming data is used. All 12 titles, descriptions, cover
graphics, regions, telemetry patterns, and anomaly signals are original synthetic data generated by
the application. The demo discloses this clearly.

## Challenges

The central challenge was making agentic analysis reliable without allowing a model to freely write
SQL or invent business impact. We solved it with deterministic statistical gates, fixed validated
query builders, an official MCP server backed by a database read-only identity, auditable impact
math, and structured Gemini output only after an anomaly is real.

## Accomplishments

- A real end-to-end event → ClickHouse → MCP → four-agent → approval flow.
- A live, controllable anomaly that becomes an incident in seconds.
- Quantified impact and an explicit calculation methodology on every incident.
- A visible human gate with no hidden execution capability.
- Automated policy, unit, API, and real MCP integration tests.

## What we learned

Agent reliability improves when models receive bounded evidence and immutable calculations rather
than a blank SQL surface. ClickHouse is especially effective here because short-window operational
queries and longer baselines can share the same real-time store without adding a separate analytics
pipeline.

## What's next

Production extensions include tenant-scoped baselines, learned seasonal thresholds, incident
feedback calibration, private service ingress, and connectors that prepare—but still never execute—
changes in real streaming operations platforms.
